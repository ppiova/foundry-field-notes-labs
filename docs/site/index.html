03

A REPEATABLE LEARNING PATH

Predict. Inspect. Change one thing.

01 / THE PROBLEM

Make a prediction

Read one synthetic input before looking at the answer. Separate what was reported from what has been verified.

02 / THE OUTPUT

Identify what ran

Simulation, replay, and live inference are different. Know which one produced the output before interpreting it.

03 / THE APPLICATION

Trace the C#

Find the input contract, provider boundary, output checks, and business rule. Valid structure does not establish semantic correctness.

04 / THE REVIEW

Test the boundary

Change a quote, a threshold, or a reviewed answer. Observe what changes and what still requires human judgment.

The reusable pattern is responsibility, not a particular SDK. Foundry supplies inference. Your application owns validation and review policy. A person resolves what remains uncertain.
What do I need to run the actual applications?

The website itself needs only a browser. The .NET apps need Git, PowerShell 7, and the exact SDK in global.json: .NET 11 RC1. The Lab 001 Foundry connector and Lab 002 decision model are treated as preview in this snapshot.

.\scripts\Test-Prerequisites.ps1
.\Start-Demo.ps1 -Lab 1 -Offline
# Or, in a separate terminal:
.\Start-Demo.ps1 -Lab 2 -Offline

Lab 001 opens at http://localhost:5187; Lab 002 at http://localhost:5190. Package restore can require internet even in offline mode. Stop each server with Ctrl+C.

05

BEFORE GOING LIVE

Learn offline. Choose live deliberately.

No hidden model calls

These pages do not call Azure. Live app runs require your selected deployment and explicit authorization for inference charges. Hosting is a separate choice.

No silent fallback

A failed live call stays an error. A presenter can switch explicitly to an offline path, but must not call that a successful live retry.

No quality shortcut

Simulation is not AI-quality evidence. Replay is not current service availability. Synthetic evaluation is not an industry benchmark.

No production approval claim

The labs teach local review, not durable audit trails. Use synthetic data and keep credentials and customer content out of demonstrations.

Grounded in code and official references
