THE BUSINESS PROBLEM

A reported outage is not a verified diagnosis.

A support operator needs a classification, a suggested next step, and a draft reply. The application must preserve what the requester actually said without pretending it confirmed the cause, contacted anyone, or restored service.

Original + human edits
Simulation takes a different path. In the local app, Triage.Simulate replaces the model call with keyword rules, then uses the same output validation. It does not execute MAF. This website only explains that path.
Is this a Foundry hosted agent?

No. In the live lab, AIProjectClient.AsAIAgent defines the agent in application code. It does not create a service-managed agent resource. The agent runs in the .NET application, with no tools or conversation memory in this sample. App Service hosting is optional and separate from model inference.

Direct model inference would also solve this one-shot task. The framework provides a small agent boundary for learning; multiple agents would not improve the explanation.

Evidence membership experiment

Empty evidence, more than 3,000 characters, or text absent from the request is rejected. Matching is case-sensitive; whitespace is not normalized.

EVIDENCE MEMBERSHIP ONLY

Quote found, interpretation not verified

This excerpt appears exactly in the request. It does not establish the cause, scope, or correctness of the proposed response. Human review is still required.

A real quote can support a wrong interpretation. Evidence membership rejects invented quotations. It does not prove that a database failed, that every user is affected, or that the proposed next step is appropriate.

YOUR LIVE PRESENTATION

Start with the report. End with the boundary.

  1. 00:00 / 2 MIN

    Name the problem and mode

    "We want a reviewable proposal, not an autonomous support action." State that the displayed result is deterministic simulation, not a model recording.

  2. 02:00 / 4 MIN

    Read the outage case

    Ask what is known. Show the expected category and priority, then try the invented quote. Explain why a matching quote still does not prove a diagnosis.

  3. 06:00 / 4 MIN

    Open the C#

    Show the live agent invocation and the shared validator. The agent definition belongs to the app; inference belongs to Foundry. Simulation bypasses the agent.

  4. 10:00 / 3 MIN

    Demonstrate review in the separate app

    Analyze Service outage in simulation mode. Edit the reply, approve it, then edit again to clear approval. Export and point out originals versus human edits.

  5. 13:00 / 2 MIN

    Close with what remains unproven

    "We validated the shape and the quotation. A person must still judge the interpretation." Leave room for a question.

Prerequisites, live setup, costs, and cleanup
Presenting live is not the same as running live inference. For an actual model call, select your own deployment and authorize consumption first. Show a failure honestly; never relabel simulation as a successful Foundry response.
06

WHAT THIS DEMO DOES NOT PROVE

Keep the claim smaller than the evidence.

Simulation is not AI quality

Keyword rules reproduce the workflow but can mishandle negation or mixed intent. Their output and timing do not measure a model.

Instructions are not a guarantee

Asking the model to ignore embedded commands is useful guidance, not proof against every adversarial request. Inputs and outputs remain untrusted.

Local approval is not an audit trail

The app's review state is in browser memory. It is not persisted or an identity-verified approval. Nothing is sent.

A past run is not the next run

The repository records dated live observations separately. This website makes no new inference call and does not verify your credentials, access, or deployment.
